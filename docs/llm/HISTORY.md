Seeded with 16 entries (DF-001..DF-016) distilled from `plaud-mirror`'s v0.1.0 → v0.4.13 experience over April 2026: four came from an explicit GPT-5 review at v0.4.13 (DEPLOY_PLAYBOOK.md bash block still recommending `vxcontrol/kali-linux` after the policy was reversed everywhere else; HOW_TO_USE.md with `<!-- doc-version -->` marker but absent from the sync manifest and stuck at v0.1.0 prose at v0.4.13; HANDOFF Current Status carrying `Next: rebuild + push` after the push happened; asymmetric enforcement between circuit-core docs and peripheral runbooks); the remaining twelve were distilled from personal-memory feedback the downstream LLM assistant had saved to itself across the same period. Categories used: `drift` (content inconsistent, marker/date checks do not catch), `gap` (class of file/behaviour the validator does not track at all), `usability` (rule exists but easy to violate), `process` (workflow mismatch around DocKit). Status values: `open` / `accepted` / `implemented` / `rejected` / `superseded-by: DF-NNN`. Entries never get deleted — implemented/rejected become audit trail. `DF-005` is already `implemented` (closed by the existing `handoff-start-here-sync` check); the other fifteen are `open`. File placement: peer to the existing planning docs (`DEFERRED_NEXT_VERSION`, `HOOKS_ENFORCEMENT_PROPOSAL`, `LLM_DOCKIT_CE_V2_PROPOSAL`, `EXTERNAL_CONTEXT_PLUGIN_PLAN`) under `docs/`, not in `docs/llm/` (not per-session working memory). Explicit `skip` entry added to `dockit-sync-manifest.yml` so the log stays DocKit-only and is never propagated to adopters. Meta-observation at the bottom of the file: DocKit currently enforces structural discipline (markers, dates, manifest membership, paired-file sync) excellently and semantic discipline not at all; every implemented check is about artifact shape; every open entry is about artifact content. That observation is the through-line the next round of validator/template work should answer. No validator or template change ships in this minor — the log is preparatory backlog.
